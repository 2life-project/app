# AGENTS.md — закон проекта

Читает и человек, и агент, каждую сессию. Если правка нарушает эти правила —
правка неверна, даже когда работает. Целевая архитектура — в
[docs/architecture.md](docs/architecture.md), принятые решения и их триггеры —
в [docs/decisions.md](docs/decisions.md), токены — в
[docs/design-tokens.md](docs/design-tokens.md).

Мобильное приложение 2Life: iOS и Android, Expo SDK 57 · React Native 0.86 ·
React 19.2 · expo-router · TypeScript strict. Алиас `@/*` → `src/*`.

---

## 0. Главное правило: код подтягивают к правилам, а не наоборот

1. **Не бери соседний файл за образец.** Эталон — этот файл и `docs/`, а не то,
   как сделано рядом. «Вокруг все так делают» означает, что вокруг все делают
   неправильно.
2. **Правило бойскаута.** Тронул область — приводи к правилам всю тронутую
   область, а не свою строку. Оставлять рядом старьё «потому что не моя строка»
   нельзя.
3. **Простота считается по проекту, а не по диффу.** Прежде чем добавлять
   абстракцию, спроси, нельзя ли что-то удалить. Но мелкий костыль остаётся
   костылём: если общее решение убирает дубль в N местах — оно правильнее.
4. **Никаких TODO и обходов.** Нет `// TODO: потом`, `as any`, магических чисел
   «чтобы заработало». Нужна инфраструктурная правка — сделай её один раз.

## 1. Прежде чем писать код

1. **Проверь версию API.** Expo и React Native ломают API между минорами.
   Документация ровно этого SDK: <https://docs.expo.dev/versions/v57.0.0/>.
   Не по памяти.
2. **Найди, где это уже сделано.** Компонент, токен, хелпер — сначала поиск по
   `src/shared`, потом код. Дублировать существующее запрещено.
3. **Самая маленькая правка, которая решает задачу.** Абстракция вводится со
   второго реального потребителя, не «на будущее».

## 2. Слои и направление зависимостей

```
src/app  →  src/features  →  src/shared  →  src/core
```

Стрелка = «может импортировать». Обратно — никогда.

| Каталог              | Что там лежит                                                   | Чего там быть не должно     |
| -------------------- | --------------------------------------------------------------- | --------------------------- |
| `src/app`            | только роутинг expo-router: `_layout`, файлы-экраны             | вёрстка, запросы, состояние |
| `src/features/<имя>` | одна продуктовая область: `ui/`, `model/`, `api/`               | всё, что нужно двум фичам   |
| `src/shared`         | переиспользуемое без знания о продукте: `theme/`, `ui/`, `lib/` | импорт конкретной фичи      |
| `src/core`           | инфраструктура: конфиг, HTTP, логи                              | UI, продуктовые понятия     |

- Фича наружу видна только через `src/features/<имя>/index.ts`.
- Фича не импортирует другую фичу — ни алиасом, ни относительным путём выше
  своего корня. Общее уезжает в `shared`.
- Экран в `src/app` тонкий: подключает фичу и всё.

## 3. MUST NOT

- ❌ Литеральный цвет, кегль, интерлиньяж, начертание, гарнитура, отступ,
  радиус вне `src/shared/theme` — всё это токены.
- ❌ `<Text>` из react-native напрямую — только `Text` из `@/shared/ui`.
- ❌ `console.*` — только `logger` из `@/core/log/logger`.
- ❌ `any`, `as any`, `as never`. Приведение типа без объяснения в комментарии.
- ❌ Продуктовый текст ошибки из ответа сервера в интерфейс. Показывать
  собственную формулировку, сырой ответ — в лог.
- ❌ Определять успех по тексту ошибки. Только по коду.
- ❌ Ручная правка `src/shared/theme/palette.gen.ts` — он собирается `make tokens`.
- ❌ Бизнес-логика в компоненте: вычисления и побочные эффекты живут в `model/`.
- ❌ Файл длиннее 300 строк (цель — 200). Растёт — выноси части.
- ❌ Загрузка файла через `request` из `@/core/http/client`: тело там только
  JSON. Файлы — через `expo-file-system`.
- ❌ Адрес экрана строкой: `router.push('/journal')`. Только `to` из
  `@/shared/nav`.
- ❌ Чтение параметров маршрута внутри фичи. Их читает файл маршрута и
  передаёт пропсом.

## 4. MUST

- ✅ Экран — композиция: данные из `model/`, разметка из `@/shared/ui`.
- ✅ Стили — `StyleSheet.create` на уровне модуля, с импортом `theme`.
- ✅ Неизменяемые значения — вне компонента: конфиги, массивы опций, стили.
- ✅ Комментарий объясняет **почему**, а не что. «Что» видно в коде.
- ✅ Тест там, где есть логика: разбор, вычисление, ветвление. Рядом с кодом:
  `greeting.ts` → `greeting.test.ts`. Вёрстку снапшотами не покрываем.
- ✅ Зависимость ставится через `npx expo install <пакет>` и только когда своими
  силами дороже. В описании PR — строка, зачем она.
- ✅ Разрешение (камера, галерея, уведомления) добавляется в `app.json` тем же
  коммитом, что и код, который его просит. iOS не показывает диалог об ошибке —
  система убивает процесс, если usage-строки нет.
- ✅ `ios/` и `android/` не коммитятся: генерируются `make prebuild`. Нативная
  настройка живёт в `app.json` и config-плагинах.

## 5. Что держит линтер, а что ревью

Правило без зубов — это пожелание. Здесь честно разделено.

**Ловит `make check` (ошибка сборки):**

| Правило                                                | Чем                          |
| ------------------------------------------------------ | ---------------------------- |
| Направление зависимостей между слоями                  | `import/no-restricted-paths` |
| Импорт чужой фичи и обход её публичного входа          | `no-restricted-imports`      |
| Литералы цвета, кегля, отступа, радиуса                | `no-restricted-syntax`       |
| `console.*`                                            | `no-console`                 |
| Мёртвые импорты и переменные                           | `unused-imports`             |
| Контраст, порядок ступеней, сверка цветов с `app.json` | `theme.test.ts`              |
| Расхождение палитры с рецептом                         | шаг CI после `make tokens`   |
| Битый импорт и упавший config-плагин                   | `expo export` в CI           |

**Держится ревью (линтер не поймает):** правило бойскаута, размер файла,
«почему» в комментариях, отсутствие TODO, тонкость экрана, наличие теста на
логику, выбор между «удалить» и «абстрагировать».

## 6. Прежде чем сказать «готово»

```bash
make check
```

- [ ] `make check` зелёный. Если проверка «не относится к задаче» — она всё
      равно должна быть зелёной.
- [ ] Тронутая область приведена к правилам, а не только новая строка.
- [ ] Ноль литералов вида/размера, ноль `console.*`, ноль `any`.
- [ ] Файлы меньше 300 строк.
- [ ] Копии, заменённые общим кодом, удалены везде.
- [ ] На новую логику есть тест.
- [ ] Новый общий компонент или токен сразу применён во всех подходящих местах.

## 7. Когда остановиться и спросить

- Правка требует нового слоя, новой зависимости или state-менеджера.
- Непонятно, куда положить код: граница `shared` и `features` размыта.
- Нужна доменная модель, которую читают две фичи (см. `docs/decisions.md`).
- Продуктовый текст или экран не определён — не выдумывай формулировки.
- Правка меняет решение из `docs/decisions.md`.
- Нужно тронуть сгенерированный файл руками.

## 8. Соглашения

- Комментарии в коде и документация — по-русски. Описания тестов — по-русски.
- Сообщение коммита — по-русски, по делу: что сделано и почему, без воды.
- Файлы и каталоги — `kebab-case`, компоненты — `PascalCase`, хуки — `useX`.
- `render` из `@testing-library/react-native` асинхронный: `await render(<X />)`,
  дальше `screen`.
