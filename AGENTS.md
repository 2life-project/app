# Правила работы в этом репозитории

Читает и человек, и агент. Правила обязательные: если правка их нарушает — правка неверна,
даже когда «работает».

## Что это

Мобильное приложение 2Life: iOS и Android, Expo SDK 57 + React Native 0.86, expo-router,
TypeScript в строгом режиме.

## Прежде чем писать код

1. **Проверь версию API.** Expo и React Native ломают API между минорами.
   Документация ровно этого SDK: <https://docs.expo.dev/versions/v57.0.0/>. Не по памяти.
2. **Найди, где это уже сделано.** Компонент, токен, хелпер — сначала поиск по `src/shared`,
   потом код.
3. **Самая маленькая правка, которая решает задачу.** Абстракция вводится со второго
   реального потребителя, не «на будущее».

## Слои и направление зависимостей

```
src/app  →  src/features  →  src/shared  →  src/core
```

Стрелка = «может импортировать». Обратно — никогда, это проверяет линтер.

| Каталог              | Что там лежит                                                   | Что там лежать не должно    |
| -------------------- | --------------------------------------------------------------- | --------------------------- |
| `src/app`            | только роутинг expo-router: `_layout`, файлы-экраны             | вёрстка, запросы, состояние |
| `src/features/<имя>` | одна продуктовая область: `ui/`, `model/`, `api/`               | всё, что нужно двум фичам   |
| `src/shared`         | переиспользуемое без знания о продукте: `theme/`, `ui/`, `lib/` | импорт конкретной фичи      |
| `src/core`           | инфраструктура: конфиг, HTTP, логи                              | UI, продуктовые понятия     |

Правила, которые нельзя обойти:

- Фича наружу видна только через `src/features/<имя>/index.ts`.
  `import { X } from '@/features/foo/ui/bar'` запрещён линтером.
- Фича не импортирует другую фичу — ни через `@/features/<имя>`, ни относительным путём
  выше своего корня. Оба пути закрыты линтером, обходить их нечем: общее уезжает в `shared`.
- Экран в `src/app` — тонкий: подключает фичу и всё. Логика на маршруте — ошибка слоя.
- Две фичи не импортируют друг друга. Общее уезжает в `shared`.

## Токены

Три уровня: сырые шкалы → смысловые роли → компонент. Компонент читает только роли.

- Цвет, отступ, радиус, тень, кегль, длительность берутся **только** из `@/shared/theme`.
- Цвет — через роли из `theme`, а не через `scales`: шкала это пигмент, роль это смысл.
- Hex-литерал в `src/**` вне `src/shared/theme/**` — ошибка линтера.
- `fontSize` в продуктовом коде не пишут: есть `<Text variant="...">`. Нужен новый размер —
  добавляется роль в `textVariant`, а не число на месте.
- Отступы — только шаг из `space`. Ручные `margin: 13` не проходят ревью.
- Стили — обычный `StyleSheet.create` с импортом `theme`. Тема одна, хуков и провайдера нет.
- `palette.gen.ts` руками не правят: он собирается из рецепта командой `make tokens`.
- `useColorScheme` не зовут: тема одна, и тёмной не будет, пока не появится её макет.

Подробности и порядок добавления токена — `docs/design-tokens.md`.

## Код

- TypeScript строгий. `any` и `as` без объяснения в комментарии — не проходят.
- `console.*` запрещён линтером. Логи — через `logger` из `@/core/log/logger`.
- Новая зависимость ставится через `npx expo install <пакет>` (он выберет версию под SDK)
  и только когда своими силами дороже. В PR — строка, зачем она.
- Запросы — через `request` из `@/core/http/client`. **Кроме загрузки файлов:**
  тело там только JSON, и `FormData` компилятор не пропустит намеренно. Файл
  грузят через `expo-file-system` — у него есть прогресс и продолжение в фоне.
- Разрешение (камера, галерея, уведомления) добавляется в `app.json` тем же
  коммитом, что и код, который его просит. iOS не показывает диалог об ошибке —
  система убивает процесс, если usage-строки нет.
- Нативные папки `ios/` и `android/` не коммитятся: они генерируются `make prebuild`.
  Нативная настройка живёт в `app.json` и config-плагинах.
- Скрипты запуска называются `start:ios` / `start:android` намеренно: `expo prebuild`
  молча переписывает их, если значение дословно `expo start --ios`. Не переименовывать.
- Файлы и каталоги — `kebab-case`, компоненты — `PascalCase`, хуки — `useSomething`.

## Тесты

Тест обязателен там, где есть логика: разбор, вычисление, ветвление, деньги, доступ.
Вёрстку снапшотами не покрываем. Тест лежит рядом с кодом: `greeting.ts` → `greeting.test.ts`.

`render` из `@testing-library/react-native` **асинхронный**: `await render(<X />)`, дальше `screen`.

## Прежде чем сказать «готово»

```bash
make check
```

Формат, линтер, типы, тесты. Красный `make check` — работа не сделана.
Если проверка «не относится к задаче» — она всё равно должна быть зелёной.

## Чего не делать

- Не переписывать чужой слой «заодно».
- Не добавлять state-менеджер, ORM, UI-кит и генератор форм без обсуждения.
- Не чинить симптом там, где виден корень: правь общую функцию, а не каждый вызов.
- Не отключать правило линтера, чтобы пройти проверку. Отключение — с комментарием почему.
- Не выдумывать продуктовые тексты и экраны: если непонятно, что показывать, спроси.
