# ES100: железо и датчики

Что физически стоит в браслете и что из этого доступно по протоколу. Три
источника, и они помечены отдельно: **[живое]** — снято с устройства командами,
**[SDK]** — из заголовков вендора, **[внешнее]** — из открытых источников по
платформе. Наблюдения глазами помечены **[глаз]**.

---

## 1. Паспорт **[живое]**

| Параметр              | Значение               |
| --------------------- | ---------------------- |
| Адрес                 | `D8:0F:B5:11:2E:F7`    |
| Платформа             | `NAL-WB00`             |
| Аппаратная версия     | `010404`               |
| Прошивка              | `AT519V003396`         |
| Версия протокола      | `V1.0`                 |
| Серийный              | `V1.0`                 |
| Максимальный пакет    | 244 байта              |
| Заряд на момент съёма | 93 %                   |
| Ёмкость батареи       | 220 мА·ч **[внешнее]** |

`NAL-WB00` — **не модель, а идентификатор платформы**. Его же отдают DM58,
Blackview W60, Carbinox Blaze S, Zeblaze Stratos 4 и HONOR CHOICE MOECEN Band.
Строка модели в стандартной службе у всех одна: `lark`. **[внешнее]**

## 2. Оптический датчик

### Что видно глазами **[глаз]**

- **два зелёных** светодиода — горят и мигают почти всё время;
- **два приёмника** (фотодиода) между ними;
- **красный** — виден периодически, точки различимы;
- периоды, когда «ничего не горит», — это **инфракрасный**: он невидим;
- синего не наблюдалось.

### Что следует из измерений **[живое]**

Устройство отдаёт **SpO₂** — насыщение крови кислородом. Оно считается по
отношению поглощения на двух длинах волн: **красной (~660 нм) и инфракрасной
(~940 нм)**. Одним зелёным каналом SpO₂ не считается физически. То есть красный
и ИК присутствуют не по наблюдению, а по необходимости.

Зелёный (~525 нм) — рабочая длина волны пульсометра: он меньше уходит вглубь и
устойчивее к движению.

### Что из этого выводится, а не измеряется

| Показатель           | Откуда берётся                                     |
| -------------------- | -------------------------------------------------- |
| Пульс                | форма пульсовой волны, зелёный канал               |
| SpO₂                 | отношение красного и ИК каналов                    |
| Вариабельность (HRV) | интервалы между ударами из той же волны            |
| Стресс               | производная от HRV, отдельного датчика нет         |
| Давление             | форма волны плюс калибровка, отдельной манжеты нет |
| Настроение           | производная, шкала устройства 1–5                  |

Четыре последних строки — **расчёт по одной и той же пульсовой волне**, а не
четыре разных сенсора. Точность у таких оценок соответствующая.

### Чего нет

**ЭКГ отсутствует.** Для неё нужны электроды на корпусе и разность потенциалов
между двумя точками тела — оптикой ЭКГ не снимается. В масках возможностей ЭКГ
не заявлена.

## 3. Термометр

**Датчик по протоколу недоступен. [живое]**

Два независимых подтверждения:

1. Бит `temperature` в масках возможностей **сброшен** (список 4, бит `0x200`).
2. Команды чтения температуры не отвечают вовсе:
   - `01 FB AA 01` — текущая: нет ответа;
   - `01 FB AA 02` — история за двое суток: нет ответа.

При этом в SDK вендора флаги термометра **есть** — `isHasBodyTemperature`,
`isHasCalibrateBodyTemperature`, `isHasSwitchTempUnit`, `isHasBodyTemperatureFunction2`
**[SDK]**. То есть в линейке термометр бывает, а в этой прошивке он выключен или
не установлен.

Косвенно о типе: наличие **пользовательской калибровки** в SDK — признак
контактного термистора под кожу, а не медицинского инфракрасного модуля.
Термистор меряет температуру кожи, и без калибровки под конкретного человека его
показания к температуре тела отношения не имеют. **[внешнее]**

Проверить, есть ли термистор физически, можно только вскрытием.

## 4. Движение

**Акселерометр есть заведомо:** без него не считаются ни шаги, ни дистанция, ни
стадии сна, ни распознавание активности — а всё это устройство отдаёт. **[живое]**

**Гироскоп — не установлен.** Сырые оси движения протокол не отдаёт, отдельного
флага в масках нет, а по железу свидетельства расходятся:

| Источник                                        | Что говорит                      |
| ----------------------------------------------- | -------------------------------- |
| Референс-дизайн Actions для часов **[внешнее]** | **три оси**: STK8321 или QMA6100 |
| Близнец ETERNITY ETQ16 **[внешнее]**            | шесть осей, `LSM6DSOW`           |
| Honor Band 9 на том же чипе **[внешнее]**       | шесть осей                       |
| Redmi Watch 3 Lite на том же чипе **[внешнее]** | три оси, `LIS2DW12`              |

В SDK Actions **драйверов гироскопа нет вовсе** — таблица `gyro_sensor_dev`
пустая, шесть осей подключаются мимо их слоя датчиков, ванильным драйвером
Zephyr. То есть три оси — дешёвый дефолт платформы, шесть — опция для дорогих
изделий. К какому лагерю относится ES100, снаружи не видно.

**Важная поправка.** Раньше здесь стояло, что авторегистрация активности
доказывает наличие гироскопа: библиотека распознавания якобы требует шести осей.
**Это неверно.** В пресс-релизе разработчика сказано лишь, что алгоритмы
«адаптированы под ходовые датчики рынка», а в стандартной сборке SDK эта
библиотека собирается **под трёхосевой STK8321**. Распознавание активности
гироскопа не доказывает.

## 5. Прочее железо **[живое + SDK]**

| Узел                | Есть | Откуда известно                                          |
| ------------------- | ---- | -------------------------------------------------------- |
| Микрофон            | ✓    | диктофон работает, Opus 16 кГц                           |
| Вибромотор          | ✓    | команда «найти браслет» отрабатывает                     |
| Светодиод-индикатор | ✓    | двухцветный, виден глазами                               |
| Экран               | ✗    | бит `noScreen` взведён                                   |
| Динамик             | ✗    | звук наружу не выводится                                 |
| GPS                 | ✗    | бит сброшен, трек пуст                                   |
| NFC                 | ✗    | в масках не заявлен                                      |
| Магнитометр         | ✗    | в масках не заявлен                                      |
| Bluetooth Classic   | ✗    | бит `noBluetoothCall` взведён — звонки не поддерживаются |

### Процессор — Actions, серия `lark`, Cortex-M4 **[живое + внешнее]**

Доказывается тремя независимыми способами, и все три опираются на то, что
изготовитель не переопределил заводские значения в прошивке.

1. **Служебные каналы.** У браслета есть две служебные BLE-службы:
   `e49a25f8-f69a-11e8-8eb2-f2801f1b9fd1` и `e49a3001-f69a-11e8-8eb2-f2801f1b9fd1`.
   Оба UUID лежат **дословно** в исходниках SDK Actions на базе Zephyr: первый —
   канал обновления прошивки, второй — отладочный журнал.
2. **Заглушки в стандартной службе.** `Manufacturer Name = "Manufacturer"` и
   `PnP ID = 01 00 00 00 00 01 00` — это ровно значения по умолчанию из
   конфигурации Actions. Изготовитель их не заполнил.
3. **Имя модели.** `Model Number = "lark"` — это не модель, а **кодовое имя
   серии кристалла**: в конфигурации Zephyr поле модели по умолчанию равно
   идентификатору SoC. Серия `lark` — ядро Cortex-M4, вторая серия у Actions
   называется `leopard` и построена на Cortex-M33.

Точный номер внутри серии `lark` по этой цепочке не устанавливается: публичной
таблицы серии нет. Известно, что `ATS3085S` **исключается** — он из `leopard`.
Наиболее вероятен **ATS3085L**, но это вывод по аналогии, а не документ.

**Опровергнутая версия.** Служебные UUID сначала были приняты за канал JieLi
(杰理) — из-за метода `sendDataToJlDevice` в SDK вендора. Проверка показала
обратное: у JieLi свои UUID (`AE00`/`AE01`/`AE02`), на браслете их нет, а метод
относится к аудио-ветке того же SDK и для браслета мёртв.

**Про малошумящий стабилизатор под пульсометр** — раньше здесь утверждалось, что
он встроен в кристалл. Подтверждения этому нет. Наоборот: в референс-плате
питание оптического датчика идёт с обычной ноги, а документация самих
PPG-сенсоров рекомендует ставить стабилизатор **внешним**.

### Карта служб совпадает с DM58 один в один **[внешнее]**

У браслета DM58, разобранного независимо, тот же набор служб и характеристик до
последнего идентификатора: `180a`, `ffd0`, `e49a3001`, `e49a25f8`, `55ff`, `56ff`
с теми же характеристиками, и та же модель `lark`. Это одна белолейбловая
платформа.

## 6. Маски возможностей: что заявляет само устройство **[живое]**

Прочитаны с характеристик `35F1` и `34F1`:

```
35F1  80 00 00 00 00 00 00 00 50 0d 80 80 00 00 4e 00 01 00 00 00
34F1  00 f4 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 20
```

Разобранные списки:

```
список 2 = 0x4E0001    список 4 = 0x500D80    список 8 = 0x000020
список 3 = 0x800000    список 7 = 0x008000    максимальный пакет = 244
```

| Возможность               | Есть | Комментарий                                     |
| ------------------------- | ---- | ----------------------------------------------- |
| Диктофон                  | ✓    | подтверждено работой                            |
| Вариабельность пульса     | ✓    |                                                 |
| Давление                  | ✓    | расчётное, по пульсовой волне                   |
| Настроение                | ✓    | шкала 1–5, значения вендором не документированы |
| Расширенные будильники    | ✓    |                                                 |
| Расширенная история       | ✓    | меняет номер поля в запросе счётчика кадров     |
| Голос офлайн              | ✓    | **бит взведён, смысл не установлен**            |
| Нет экрана                | ✓    |                                                 |
| Нет звонков по BT Classic | ✓    |                                                 |
| Термометр                 | ✗    | и командами не отвечает                         |
| Музыка                    | ✗    |                                                 |
| Распознавание речи        | ✗    | на устройстве не делается                       |
| ChatGPT                   | ✗    |                                                 |
| GPS                       | ✗    |                                                 |

**Про «голос офлайн».** Бит взведён, но команд под него в протоколе не нашлось, а
распознавание речи при этом выключено. Что именно за ним стоит — не установлено;
выдавать это за офлайн-транскрипцию нельзя.

**Четыре бита не опознаны:** список 2 биты 0 и 22, список 4 бит 10, список 7
бит 15, список 8 бит 5. Что они означают, в доступных источниках не описано.

## 7. Текущие настройки датчиков **[живое]**

| Настройка              | Значение                                  |
| ---------------------- | ----------------------------------------- |
| Непрерывный пульс      | включён                                   |
| Интервал замера пульса | 1 минута                                  |
| Интервал замера SpO₂   | 10 минут                                  |
| Верхний порог пульса   | 180 уд/мин, тревога включена              |
| Нижний порог пульса    | 50 уд/мин, тревога выключена              |
| Сахар в крови          | заявлен, датчика нет — поле всегда пустое |
| Состояние ношения      | надет                                     |
| Погода                 | выключена                                 |

**Темп живого канала — ровно 10 секунд**, и он не меняется при движении.
Меняется набор показателей: в покое приходит пульс (покоя, максимальный,
минимальный, средний), при движении — SpO₂. Проверено наблюдением 90 секунд.

## 8. Какой пульсометр может стоять **[внешнее]**

Точная модель не установлена. Но круг кандидатов сузился: в SDK производителя
кристалла есть драйверы ровно для трёх семейств оптических датчиков.

| Семейство   | Изготовитель     | Модели в SDK   |
| ----------- | ---------------- | -------------- |
| Goodix      | 汇顶科技         | GH3011, GH3x2x |
| Vcare       | 成都维客昕微电子 | VC9201, VC9202 |
| Tianyihexin | 天易合芯         | HX3605, HX3690 |

**Ничего из TI, Analog Devices, Silicon Labs и Hicling в этом SDK нет** — эти
кандидаты отпадают.

Что известно про конфигурацию тех, у кого нашлась документация:

| Датчик | Светодиоды                        | Приёмники |
| ------ | --------------------------------- | --------- |
| HX3605 | три канала на общем драйвере тока | **один**  |
| VC31B  | каналы зелёного и инфракрасного   | **один**  |

Три светодиода на один приёмник — типовой браслетный минимум под «пульс плюс
SpO₂»: зелёный, красный, инфракрасный.

**Расхождение, которое честно оставить открытым.** Глазами на браслете видно
**два зелёных и два приёмника**, а у обоих задокументированных кандидатов
приёмник **один**. Значит либо стоит датчик другой модели, либо за одно окно
видно несколько кристаллов в общем корпусе. Подгонять наблюдение под найденную
документацию не буду.

У родственных изделий на этой же платформе вскрытием подтверждены: **天易合芯**
в Redmi Watch 3 Lite и **Vcare VC30F / VC30F-S** в Blackview W60 и DM58.

## 9. Чего установить не удалось

1. **Точное число светодиодов и фотодиодов** и модель оптического датчика —
   протокол об этом не сообщает, вскрытия ES100 в открытых источниках нет.
2. **Есть ли гироскоп физически.** Референс платформы — три оси, у близнеца
   ETQ16 заявлены шесть. Только вскрытием или запросом вендору.
3. **Точный номер кристалла внутри серии `lark`.**
4. **Есть ли термистор физически** — по протоколу он недоступен, это всё, что
   известно.
5. **Смысл бита «голос офлайн»** и четырёх неопознанных битов.

**Отладочный журнал устройства проверен и молчит.** У браслета активен служебный
канал `e49a3001`, в который прошивка Actions при старте печатает имена и
идентификаторы найденных датчиков. Подписка на него держится, но за две минуты
не пришло ни байта: в серийной сборке журнал выключен. Путь снять модели
датчиков без вскрытия — не сработал.
