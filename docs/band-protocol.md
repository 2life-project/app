# ES100: протокол обмена

Техническая документация нижнего уровня: как приложение разговаривает с
браслетом. Кадры, номера команд, раскладки байт, порядок обмена.

Три документа про браслет разделены так:

| Документ                             | О чём                                             |
| ------------------------------------ | ------------------------------------------------- |
| [band-hardware.md](band-hardware.md) | что физически внутри: датчики, память, кристалл   |
| **этот**                             | как с устройством говорить: биты, байты, команды  |
| [band-module.md](band-module.md)     | что из этого отдаёт наш модуль: API, типы, данные |

Всё описанное снято с живого устройства и сверено с заголовками SDK вендора.
Где проверить было не на чем — это сказано прямо, а не заполнено догадкой.
Реализация лежит в `src/features/band/api`.

## 1. Что за устройство

| Параметр           | Значение                                  |
| ------------------ | ----------------------------------------- |
| Модель             | ES100                                     |
| Платформа          | `NAL-WB00`, кристалл Actions серии `lark` |
| Аппаратная версия  | `010404`                                  |
| Прошивка           | `AT519V003396`                            |
| Версия протокола   | `V1.0`                                    |
| Протокол           | вендор UTE, диалект JX                    |
| Адрес проверенного | `D8:0F:B5:11:2E:F7`                       |
| Максимальный пакет | 244 байта                                 |

Четыре свойства меняют всё остальное:

1. **Экрана нет.** Есть одна кнопка и двухцветный светодиод. Всё, что прошивка
   умеет показывать — вибрация. Настройки экрана в протоколе остались (прошивка
   общая на линейку) и читаются, но ни на что не влияют.
2. **Соединение одно.** Пока браслет занят нашим приложением, фирменная
   программа вендора его не увидит, и наоборот.
3. **Часы теряются при разрыве связи.** Время устройства — единственный
   идентификатор голосовой записи, поэтому выставлять его надо при каждом
   подключении.
4. **Идентификатора запроса в протоколе нет.** Ответ узнаётся по номеру команды,
   режиму и полю — значит команды идут строго по одной.

## 2. Радио

### 2.1. Реклама и поиск

| Что                | Значение                                            |
| ------------------ | --------------------------------------------------- |
| Имя                | `ES100` (бывает пустым, пока устройство не ответит) |
| Рекламируемый UUID | `00005555-0000-1000-8000-00805f9b34fb`              |
| Данные вендора     | 2 байта кода производителя, дальше 6 байт MAC       |
| Окно поиска        | 30 с — устройство рекламирует себя с паузами        |

Фильтр по `0x5555` задаётся радио, а не проверяется после: без него в списке
оказываются наушники, телевизоры и чужие часы.

**MAC в рекламном пакете важен.** iOS не отдаёт приложению системный адрес — он
выдаёт собственный UUID, свой на каждом телефоне. Адрес из рекламы виден до
подключения, и только по нему браслет опознаётся как тот же самый.

**Подключённое устройство рекламу прекращает.** Браслет, оставшийся на связи с
системой, прошлым запуском или программой вендора, поиском не находится никогда.
Такие берутся у системы отдельно — запросом подключённых устройств по всем трём
службам браслета.

### 2.2. Службы и характеристики

| Служба       | Характеристика | Роль                                                |
| ------------ | -------------- | --------------------------------------------------- |
| `0x5555`     | —              | только реклама, обмена по ней нет                   |
| `0x56FF`     | `0x34F1`       | **запись команд** без подтверждения                 |
| `0x56FF`     | `0x34F2`       | **уведомления**: ответы и самостоятельные отчёты    |
| `0x56FF`     | `0x34F1`       | **чтение**: старшие маски возможностей + MTU        |
| `0x55FF`     | `0x35F1`       | **чтение**: младшие маски возможностей              |
| `0x180A`     | стандартные    | `Manufacturer = "Manufacturer"`, `Model = "lark"`   |
| `e49a25f8-…` | —              | канал обновления прошивки Actions                   |
| `e49a3001-…` | —              | отладочный журнал Actions, в серийной сборке молчит |

Характеристика `0x34F1` работает в обе стороны: в неё пишутся команды, и из неё
же читаются старшие маски. Это не опечатка — так устроена прошивка.

### 2.3. Правила обмена

| Правило                | Значение          | Почему                                                    |
| ---------------------- | ----------------- | --------------------------------------------------------- |
| Пауза между записями   | 80 мс             | вплотную прошивка теряет кадры; в SDK вендора стоит 40 мс |
| Запрошенный MTU        | 247               | устройство отвечает «максимальный пакет 244»              |
| Одновременных запросов | 1                 | опознавателя запроса в кадре нет, ответы перепутаются     |
| Ожидание ответа        | 12 с              | выгрузка истории отвечает не мгновенно                    |
| Ожидание файла записи  | 120 с             | звук идёт отдельным потоком кадров                        |
| Запись                 | без подтверждения | `writeCharacteristicWithoutResponse`                      |

Отказ записи с кодом «устройство не подключено» — приговор всему сеансу, а не
одной команде: через ту же характеристику идёт каждая команда.

## 3. Кадр основного протокола

```
01 | CMD | MODE | FIELD | [LEN | payload]
```

- `01` — заголовок, первый байт любого кадра;
- `CMD` — группа команд (см. §6);
- `MODE` — `AA` чтение, `AB` запись, `AC` самостоятельный отчёт устройства;
- `FIELD` — номер поля внутри группы;
- `LEN` — длина полезной нагрузки. **Присутствует только когда нагрузка есть.**

Поэтому `01 A4 AA 16` — законченный запрос из четырёх байт, а не обрезанный.

**Запрос всех полей группы:** режим дублируется вместо номера поля —
`01 A4 AA AA`. Так читаются паспорт, сводка дня, будильники, каталог видов
спорта, состояние оператора и типы уведомлений.

**Номера полей у чтения и записи разные даже для одной настройки.** Язык
читается полем `08`, а пишется полем `06`. Автозамер стресса читается полем
`12`, а пишется парой `07` и `0D`. Выводить одно из другого нельзя — команды
перечисляются явно.

### 3.1. Многокадровый ответ

Ответ на один запрос приходит несколькими уведомлениями:

```
01 CMD MODE FIELD | SEQ | payload      ← кадр данных, SEQ растёт
01 CMD MODE FIELD | FD  | XOR          ← терминатор с контрольной суммой
```

- `SEQ` — номер кадра. Склеивать надо **по возрастанию номера**, а не по порядку
  прихода: при потере и повторе куски встанут не туда.
- `FD` — маркер последнего кадра. Дальше данных не будет.
- `XOR` — контрольная сумма: побайтовый XOR **всех кадров данных вместе с их
  заголовками**. По одной полезной нагрузке она не сходится.

**Две группы нумеруют кадры двумя байтами** и закрываются двойным `FD FD`:
`E8` (тренировки) целиком и поле `04` группы `C6` (сон). Перепутать — значит
потерять все кадры кроме последнего: они схлопнутся в один ключ и молча
перезапишут друг друга.

### 3.2. Что приходит мусором

Устройство иногда присылает короткие кадры чужого протокола. Кадр короче четырёх
байт или с первым байтом не `01` — не ошибка разбора, а нормальный шум; падать на
нём нельзя.

Кадр ровно из четырёх байт — пустой ответ «поля нет или данных нет».

## 4. Полезная нагрузка: два вида TLV

Устройство упаковывает значения двумя похожими, но **разными** способами.
Спутать их — получить сдвиг на байт и правдоподобный мусор вместо ошибки.

| Вид       | Раскладка                         | Где встречается                       |
| --------- | --------------------------------- | ------------------------------------- |
| обычный   | `тег \| длина \| значение`        | ответ на запрос одного поля           |
| модальный | `AA \| поле \| длина \| значение` | ответ на запрос всей группы (`AA AA`) |

В модальном байт режима повторяется перед каждым тегом и при разборе
отбрасывается.

### 4.1. Числа

Порядок байт в основном протоколе — **старшим вперёд**. Целое из значения поля
собирается по всей его длине, какой бы она ни была (1, 2, 4 байта).

**У диктофона порядок обратный — младшим вперёд.** Это отдельная подсистема, см.
§9. Перепутанный порядок даёт правдоподобные, но неверные идентификаторы записей.

### 4.2. Строки

**Кодировка определяется полем, а не содержимым.**

| Что                                            | Кодировка |
| ---------------------------------------------- | --------- |
| версии, модель, серийный номер, платформа      | ASCII     |
| имена будильников, контакты, текст уведомлений | UTF-16BE  |

Признака кодировки в кадре нет — вызывающий обязан знать, что читает. Угадывать
по нулевым байтам нельзя: имя целиком из кириллицы даёт пары вида `04 xx`, ни
одного нуля, и такая догадка молча выдаст мусор.

### 4.3. Время

Четыре байта, старшим вперёд, обычный unix epoch в секундах. Часового пояса
устройство не хранит: оно живёт по времени, которое ему выставил телефон.

## 5. Многокадровая запись

Настройки, где значений несколько — будильники, профиль, уведомления, команда
тренировки — отправляются пачкой:

```
01 CMD AB FIELD | 00 | payload[0..229]     ← кадры с растущим номером
01 CMD AB FIELD | 01 | payload[230..]
01 CMD AB FIELD | FD | XOR                 ← терминатор
```

- в кадр влезает **230 байт** нагрузки при MTU 247;
- `FIELD` в пачке обычно равен байту режима (`AB`) — так протокол помечает «все
  поля группы»;
- `XOR` считается по всем отправленным кадрам, включая повторяющиеся заголовки;
- поля внутри нагрузки идут записями `AB | тег | длина | значение`.

Пачкой пишутся: будильники (`C7`), уведомление (`B0`), разрешение на звонки и
сообщения (`B2`), профиль (`C2`), дневная цель (`C1`), автозамер стресса (`E1`),
команда тренировки (`E5`).

**Байт группы у профиля, цели и стресса вендор не пишет литералом** — он
собирает кадр как `[i>>8][i&0xff] [i2>>8][i2&0xff] [секция]`, где `i` это
`0x01<группа>`, а `i2` — `<режим><поле>`. Отсюда `481 → 01 E1`, `450 → 01 C2`,
`449 → 01 C1`. Правило проверено на пяти командах с заведомо известными группами
и подтверждено живой записью.

## 6. Справочник команд

Группы, которые встречаются в обмене:

| Код  | Группа                                       |
| ---- | -------------------------------------------- |
| `A3` | время                                        |
| `A4` | паспорт устройства                           |
| `A5` | система: язык, единицы, поиск, сброс, пароль |
| `A6` | двусторонние настройки                       |
| `B0` | уведомление                                  |
| `B1` | лимиты уведомлений                           |
| `B2` | разрешение на звонки и сообщения             |
| `B3` | типы сообщений                               |
| `C1` | дневная цель                                 |
| `C2` | профиль человека                             |
| `C3` | сводка дня                                   |
| `C4` | напоминания и вторая половина здоровья       |
| `C5` | счётчики кадров истории                      |
| `C6` | история и живой отчёт                        |
| `C7` | будильники                                   |
| `E0` | погода                                       |
| `E1` | здоровье                                     |
| `E5` | оператор тренировки                          |
| `E7` | аккаунт и привязка                           |
| `E8` | тренировки                                   |
| `EA` | «не беспокоить»                              |
| `EC` | виды спорта                                  |

### 6.1. Устройство и время

| Действие            | Кадр                                             |
| ------------------- | ------------------------------------------------ |
| Паспорт целиком     | `01 A4 AA AA`                                    |
| Заряд               | `01 A4 AA 16`                                    |
| Имя вендора         | `01 A4 AA 0C`                                    |
| Время на устройстве | `01 A3 AA AA`                                    |
| Выставить время     | `01 A3 01 04 <BE32 epoch> 10 02 <зона> <минуты>` |

Установка времени идёт **без байта режима**: сразу за номером группы начинаются
записи `тег | длина | значение` — `01 04 <время>` и `10 02 <зона><минуты>`.
Смещение часового пояса кодируется старшим битом как знаком: `0x80 | часы` для
востока от Гринвича, просто `часы` — для запада.

### 6.2. Система

| Действие                   | Чтение        | Запись                             |
| -------------------------- | ------------- | ---------------------------------- |
| Язык прошивки              | `01 A5 AA 08` | `01 A5 AB 06 01 <код>`             |
| Список поддержанных языков | `01 A5 AA 03` | — (у ES100 пуст)                   |
| Единицы длины              | `01 A5 AA 04` | `01 A5 AB 07 01 <0 м \| 1 мили>`   |
| Единицы веса               | —             | `01 A5 AB 09 01 <0 кг \| 1 фунты>` |
| Таймаут экрана             | `01 A5 AA 09` | `01 A5 AB 08 01 <секунды>`         |
| Варианты таймаута          | `01 A5 AA 0B` | —                                  |
| Автоподсветка              | `01 A5 AA 06` | —                                  |
| Состояние поиска браслета  | `01 A5 AA 07` | —                                  |
| Вибрация «найти браслет»   | —             | `01 A5 AB 04 01 <0 \| 1>`          |
| Настройки одним полем      | `01 A5 AA 01` | —                                  |

**`01 A5 AA 07` — это состояние поиска браслета, а не ношения.** У вендора метод
называется `getFindWearState` и отвечает шестью байтами. Ношение опросом не
берётся вовсе, оно приходит отчётом (см. §7).

### 6.3. Здоровье

| Настройка                     | Чтение                                    | Запись                                 |
| ----------------------------- | ----------------------------------------- | -------------------------------------- |
| Автозамер пульса              | —                                         | `01 E1 AB 01 01 <0 \| 1>`              |
| Непрерывный пульс             | `01 E1 AA 10`                             | `01 E1 AB 02 01 <0 \| 1>`              |
| Интервал пульса, минуты       | `01 E1 AA 0B`                             | `01 E1 AB 0B 01 <минуты>`              |
| Интервал SpO₂, минуты         | `01 E1 AA 0C`                             | `01 E1 AB 0C 01 <минуты>`              |
| Непрерывный SpO₂              | `01 E1 AA 11`                             | `01 C4 AB 03 01 <0 \| 1>`              |
| Верхний порог пульса          | `01 E1 AA 15`                             | `01 E1 AB 03 02 <вкл> <bpm>`           |
| Нижний порог пульса           | `01 E1 AA 16`                             | `01 E1 AB 04 02 <вкл> <bpm>`           |
| Порог низкого SpO₂            | `01 C4 AA 03`                             | `01 C4 AB 04 02 <вкл> <процент>`       |
| Автозамер стресса             | `01 E1 AA 12`                             | пачка `E1`: `07 <вкл>` + `0D <минуты>` |
| Автозамер настроения          | `01 E1 AA 13`                             | `01 E1 AB 0E 01 <0 \| 1>`              |
| Автозамер давления            | `01 E1 AA 14`                             | `01 E1 AB 10 01 <0 \| 1>`              |
| Интервал стресса              | `01 E1 AA 0D`                             | (в пачке автозамера)                   |
| Интервал настроения           | `01 E1 AA 0E`                             | `01 E1 AB 0F 02 <BE16 минуты>`         |
| Интервал давления             | `01 E1 AA 0F`                             | `01 E1 AB 11 02 <BE16 минуты>`         |
| Единица давления              | `01 E1 AA 19`                             | `01 E1 AB 16 01 <единица>`             |
| Зоны пульса                   | —                                         | `01 E1 AB 08 …` 16 записей по 3 байта  |
| Напоминание о малоподвижности | `01 C4 AA 01`                             | `01 C4 AB 01 08 …`                     |
| Улучшенный разбор сна         | `01 C4 AA 02`                             | `01 C4 AB 02 01 <0 \| 1>`              |
| События тревог за период      | `01 E1 AA 01 09 <from BE32> <to BE32> 01` | —                                      |

**Зоны пульса** пишутся шестнадцатью записями `тег | 01 | значение` с тегами
`01`…`10`. Тег `0x10` у вендора повторяет значение тега `0x04` — кадр
воспроизведён байт в байт, потому что «исправить» заведомо работающий кадр
догадкой опаснее, чем повторить его как есть.

**Улучшенный разбор сна на живом устройстве включён с завода.** Значит стадии,
которые мы читаем, посчитаны самим браслетом, а не простым порогом.

### 6.4. Замеры по требованию

| Действие                  | Кадр                                   |
| ------------------------- | -------------------------------------- |
| Разовый замер (всё сразу) | `01 E1 AB 12`                          |
| Замер выбранного          | `01 E1 AB 13 03 <BE16 маска> <0 \| 1>` |

Маска типов складывается битами:

| Бит    | Что            | Бит    | Что          |
| ------ | -------------- | ------ | ------------ |
| `0x01` | пульс          | `0x10` | стресс       |
| `0x02` | SpO₂           | `0x20` | температура¹ |
| `0x04` | ЭКГ¹           | `0x40` | давление     |
| `0x08` | вариабельность | `0x80` | настроение   |

¹ У ES100 отсутствует: ЭКГ нет физически, термометр в масках возможностей
выключен и командами не отвечает.

Результат приходит **отчётом примерно через минуту**: оптический датчик
включается на измерение, а не работает постоянно.

### 6.5. История

| Действие                     | Кадр                                                |
| ---------------------------- | --------------------------------------------------- |
| Сводка дня                   | `01 C3 AA AA`                                       |
| Сколько кадров активности    | `01 C5 AA 01 08 <from BE32> <to BE32>`              |
| Кадр активности              | `01 C6 AA 01 0A <from BE32> <to BE32> <BE16 номер>` |
| Сколько кадров потока Status | `01 C5 AA 02 08 <from> <to>`                        |
| Кадр Status                  | `01 C6 AA 02 0A <from> <to> <BE16 номер>`           |
| Сколько кадров потока State  | `01 C5 AA 03 09 <from> <to> <тип движения>`         |
| Кадр State                   | `01 C6 AA 03 0A <from> <to> <BE16 номер>`           |
| Сон за период                | `01 C6 AA 04 08 <from> <to>`                        |
| Стресс за период             | `01 E1 AA 02 08 <from> <to>`                        |

**Счётчик кадров отвечает одним коротким кадром без терминатора.** Число кадров
лежит в его последнем байте. Прогонять этот ответ через сборщик многокадровых
ответов нельзя — он ждал бы терминатора до истечения времени.

Счётчик приходит **одним байтом и может соврать**: сбитый ответ превращается в
две с половиной сотни запросов по двенадцать секунд каждый. В модуле стоит
потолок — 120 кадров на историю и 60 на каждый поток распознанной активности.

**Глубина хранения на устройстве — около четырёх суток.** Измерено: счётчик
кадров растёт с периодом запроса и упирается в 37 — за сутки 20 кадров, за трое
37, за 400 дней те же 37. Самая старая запись отстояла от запроса на 3,8 суток.
Бэкфилл глубже этого невозможен.

### 6.6. Тренировки и виды спорта

| Действие                     | Кадр                                                |
| ---------------------------- | --------------------------------------------------- |
| Список тренировок            | `01 E8 AA 01 08 <from BE32> <to BE32>`              |
| Сводка тренировки            | `01 E8 AA 02 02 <BE16 id>`                          |
| Посекундный ряд              | `01 E8 AA 03 05 <BE16 id> <BE16 индекс> <алгоритм>` |
| Отрезок темпа                | `01 E8 AA 04 03 <BE16 id> <номер отрезка>`          |
| Поддерживаются ли тренировки | `01 E8 AA 07`                                       |
| Докладывать о ходе занятия   | `01 E8 AB 02 01 <0 \| 1>`                           |
| Состояние оператора          | `01 E5 AA AA`                                       |
| Команда занятия              | пачка `01 E5 AB AB …`                               |
| Каталог видов спорта         | `01 EC AA AA`                                       |

Команда занятия — пачка полей:

| Тег  | Что                                                              |
| ---- | ---------------------------------------------------------------- |
| `02` | операция: `1` старт, `2` пауза, `3` продолжить, `4` финиш        |
| `03` | тип занятия: `1` обычная тренировка                              |
| `04` | четыре нуля                                                      |
| `05` | номер вида спорта из каталога                                    |
| `06` | текущее время, BE32                                              |
| `07` | вложенный блок: дистанция, калории и секунды по три байта каждое |
| `08` | ноль                                                             |
| `09` | время старта занятия, BE32                                       |
| `0A` | ноль                                                             |
| `0B` | запретить паузу на устройстве                                    |

Ответные состояния оператора: `5` идёт, `6` на паузе, `7` не запущена. Поля `01`
в записи нет — оно только на чтение.

**Без `01 E8 AB 02 01 01` устройство ведёт занятие молча**: секундный поток
начинается только после этой команды.

### 6.7. Будильники, режимы, уведомления

| Действие                     | Кадр                                          |
| ---------------------------- | --------------------------------------------- |
| Список будильников           | `01 C7 AA AA`                                 |
| Предел числа ячеек           | `01 C7 AA 0A` → живьём `02 0A 1F`, то есть 10 |
| Запись будильников           | пачка `01 C7 AB AB …`                         |
| «Не беспокоить»              | `01 EA AA 01` / `01 EA AB 01 08 …`            |
| Лимиты уведомлений           | `01 B1 AA AA`                                 |
| Типы сообщений               | `01 B3 AA AA`                                 |
| Уведомление на браслет       | пачка `01 B0 AB AB …`                         |
| Разрешить звонки и сообщения | пачка `01 B2 AB AB …`                         |
| Двусторонние настройки       | `01 A6 AA 01`                                 |
| Поддержка погоды             | `01 E0 AA 01`                                 |

**Будильники принимаются только целиком.** Слоты, которых нет в записи,
обнуляются; команды «измени один» в протоколе нет.

**Двусторонние настройки** — список того, о смене чего устройство сообщит само.
Живьём отвечает списком из двенадцати записей.

### 6.8. Профиль и цель

Профиль (пачка `01 C2 AB AB`):

| Тег  | Значение                               | Длина |
| ---- | -------------------------------------- | ----- |
| `01` | полных лет                             | 1     |
| `02` | дата рождения: `BE16 год`, месяц, день | 4     |
| `03` | пол: `0` женский, `1` мужской          | 1     |
| `04` | рост, см                               | 1     |
| `05` | VO₂max, мл/кг/мин                      | 1     |
| `06` | когда мерили VO₂max, BE32              | 4     |
| `07` | длина шага при беге, см                | 1     |
| `08` | длина шага при ходьбе, см              | 1     |
| `09` | вес, кг                                | 1     |
| `0A` | рука: `0` левая, `1` правая            | 1     |

Дневная цель (пачка `01 C1 AB AB`): `01` вид активности, `02` тип цели,
`03` шаги (BE32), `04` калории (BE16), `05` дистанция в метрах (BE32),
`06` длительность в минутах (BE16).

**Профиль надо отправлять при привязке.** Без него браслет считает дистанцию и
калории по заводским росту, весу и длине шага, а приложение читает результат как
измеренный факт — систематическая ошибка уходит во все производные числа.

## 7. Самостоятельные отчёты

Кадры с режимом `AC` приходят без запроса. Их четыре.

| Кадр          | Что                       | Как часто                    |
| ------------- | ------------------------- | ---------------------------- |
| `01 C6 AC 01` | живой поминутный слот     | раз в 10 с, постоянно        |
| `01 E1 AC 12` | результат разового замера | ~через минуту после команды  |
| `01 E1 AC 11` | надет / снят              | по событию                   |
| `01 E8 AC 02` | секунда идущей тренировки | раз в 1 с, пока идёт занятие |

Плюс отдельным протоколом — события диктофона (§9.4).

### 7.1. Живой слот `01 C6 AC 01`

```
01 c6 ac 01 | 00 06 | 6a a0 76 66 | 08       | 58
01 c6 ac 01 | 00 0a | 6a a0 76 6a | b8 08    | 58 58 58 58
01 c6 ac 01 | 00 0d | 6a a0 76 89 | b8 88 02 | 58 58 58 58 00 03
              └длина┘ └── время ──┘ └─маска──┘ └─── значения ───┘
```

- байты 4–5 — длина остатка (в наблюдениях сходится: `06`, `0A`, `0D`);
- байты 6–9 — время BE32. **Это текущая секунда, а не начало минуты**;
- дальше маска показателей переменной длины и значения (раскладка — §8.5).

**Отчёт несёт незавершённую минуту.** Счётчики внутри неё растут от нуля к итогу
и сбрасываются на границе минуты; набор полей тоже растёт — ранний отчёт беднее
позднего. Одну минуту 23:56 устройство прислало восемью отчётами: первый с одним
полем, последние с пятью. Некоторые отчёты приходят дважды подряд с одинаковым
содержимым — это нормальная работа, а не потеря пакета.

### 7.2. Разовый замер `01 E1 AC 12`

Байты 5–8 — время BE32. С девятого байта идут записи **с двухбайтовым тегом**:
`BE16 тег | длина | значение`.

| Тег    | Что                                                  |
| ------ | ---------------------------------------------------- |
| `0x01` | пульс                                                |
| `0x02` | SpO₂                                                 |
| `0x08` | вариабельность                                       |
| `0x10` | стресс                                               |
| `0x40` | давление: два байта — систолическое и диастолическое |
| `0x80` | настроение, шкала 1–5                                |

Теги совпадают с маской типов замера из §6.4 — это одни и те же номера.

### 7.3. Ношение `01 E1 AC 11`

Байты 5–8 — время BE32, байт 10 — надет (не ноль) или снят.

**Команды чтения для ношения в протоколе нет.** Состояние известно только пока
приложение подключено; вне окна связи оно неизвестно — не «надет» и не «снят».

### 7.4. Секунда тренировки `01 E8 AC 02`

Байт 4 — номер кадра, дальше обычные записи `тег | длина | значение`:

| Тег  | Значение         | Проверено движением |
| ---- | ---------------- | ------------------- |
| `01` | секунд с начала  | 1 → 182             |
| `02` | пульс            | 87 → 110            |
| `04` | шаги             | 0 → 12              |
| `07` | дистанция, метры | 0 → 60              |
| `08` | калории          | растут ступенями    |
| `0E` | метка времени    | +1 в секунду        |
| `1A` | средний пульс    | —                   |

Номера полей сняты с работающего устройства: значения проверялись по тому, как
они менялись во время движения, а не по догадке.

## 8. Раскладки ответов

### 8.1. Паспорт `01 A4 AA AA`

Модальный TLV:

| Тег  | Поле              | Тип           |
| ---- | ----------------- | ------------- |
| `01` | MAC               | 6 байт        |
| `02` | платформа         | ASCII         |
| `03` | аппаратная версия | ASCII         |
| `08` | прошивка          | ASCII         |
| `0D` | модель            | ASCII         |
| `13` | версия протокола  | ASCII         |
| `14` | серийный номер    | ASCII         |
| `15` | системная версия  | ASCII         |
| `16` | заряд             | вложенный TLV |

Заряд внутри — обычный TLV: `01` процент, `02` заряжается, `07` тревога о низком
заряде.

### 8.2. Маски возможностей

Читаются **прямо из характеристик**, а не командой: `0x35F1` (младшая) и
`0x34F1` (старшая). Команды «перечисли, что умеешь» в протоколе нет вовсе —
`01 ED AA 02` молчит, а SDK вендора вычисляет список локально из этих же битов.

Живое устройство:

```
35F1  80 00 00 00 00 00 00 00 50 0d 80 80 00 00 4e 00 01 00 00 00
34F1  00 f4 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 20
```

Разбор:

- списки нарезаются **с конца по три байта**: последняя тройка — первый список;
- младшая характеристика даёт списки 1–6, старшая — 8–13;
- список 7 лежит отдельно: первые два байта младшей характеристики;
- первые два байта старшей — максимальный размер пакета (244).

Итог: `2 = 0x4E0001`, `3 = 0x800000`, `4 = 0x500D80`, `7 = 0x008000`,
`8 = 0x000020`, остальные нули.

Биты, на которые смотрит приложение:

| Флаг                   | Список | Бит        | У ES100 |
| ---------------------- | ------ | ---------- | ------- |
| Диктофон               | 4      | `0x100000` | есть    |
| Вариабельность пульса  | 4      | `0x800`    | есть    |
| Давление               | 2      | `0x40000`  | есть    |
| Настроение             | 2      | `0x80000`  | есть    |
| Расширенная история    | 2      | `0x20000`  | есть    |
| Двусторонние настройки | 2      | `0x400000` | есть    |
| Нет экрана             | 4      | `0x100`    | есть    |
| Нет звонков по BT      | 4      | `0x80`     | есть    |
| Нет классического BT   | 3      | `0x800000` | есть    |
| Термометр              | 4      | `0x200`    | нет     |
| Музыка                 | 4      | `0x40`     | нет     |
| Распознавание речи     | 5      | `0x4`      | нет     |
| ChatGPT                | 2      | `0x200000` | нет     |
| GPS                    | 1      | `0x100`    | нет     |

Маски меняются при обновлении прошивки, поэтому снимок имеет смысл только рядом
с её версией.

### 8.3. Сводка дня `01 C3 AA AA`

Модальный TLV. Теги `04`–`0D` — блоки по видам активности, внутри каждого
обычный TLV.

| Тег блока | Вид          | Тег блока | Вид           |
| --------- | ------------ | --------- | ------------- |
| `04`      | пробуждение  | `09`      | бег           |
| `05`      | подъём       | `0A`      | стояние       |
| `06`      | глубокий сон | `0B`      | плавание      |
| `07`      | лёгкий сон   | `0C`      | ходьба        |
| `08`      | велосипед    | `0D`      | не распознано |

Внутри блока: `01` калории, `02` дистанция в метрах, `03` набор высоты,
`04` минуты сна, `05` шаги.

Вне блоков: `01` калории за день по счёту устройства, `02` пульс на момент
выборки, `03` время выборки.

**Соответствие тега виду взято из разбора вендора, а не угадано:** номера тегов
и номера видов у него разные, прямое совпадение дало бы неверные подписи.

**Дневной итог — сумма по всем блокам.** Калории приходят несколькими блоками:
активность отдельно, базовый обмен отдельно. Взять один блок значит занизить
день. Шаги при этом складываются только по ходьбе, бегу и подъёму — сон
приезжает такими же блоками, и слепая сумма приписала бы к дневным шагам ночь.

### 8.4. Кадр истории `01 C6 AA 01`

Склеенное тело ответа:

```
<BE16 номер кадра> <BE32 время начала> затем слоты подряд:
  <BE16 смещение в минутах> <маска> <значения>
```

### 8.5. Маска поминутного слота

Маска переменной длины: старший бит байта означает «есть продолжение», поэтому
**номера битов, кратные восьми, служебные и пропускаются**. Номер бита задаёт и
смысл, и размер значения.

| Бит | Показатель                               | Байт |
| --- | ---------------------------------------- | ---- |
| 1   | шаги                                     | 1    |
| 2   | калории                                  | 1    |
| 3   | дистанция, метры                         | 2    |
| 4   | пульс покоя                              | 1    |
| 5   | максимальный пульс                       | 1    |
| 6   | минимальный пульс                        | 1    |
| 7   | пульс                                    | 1    |
| 9   | SpO₂                                     | 1    |
| 10  | пульс покоя                              | 1    |
| 11  | набор высоты, метры                      | 2    |
| 12  | средний пульс                            | 1    |
| 13  | пульс покоя                              | 1    |
| 17  | давление: систолическое и диастолическое | 2    |
| 18  | настроение                               | 2    |
| 19  | PAI низкой интенсивности                 | 2    |
| 20  | PAI средней                              | 2    |
| 21  | PAI высокой                              | 2    |
| 22  | минут в низкой                           | 2    |
| 23  | минут в средней                          | 2    |
| 25  | минут в высокой                          | 2    |
| 26  | вариабельность пульса                    | 2    |
| 27  | сахар крови ×10                          | 2    |

**Пульс покоя отображается на три разных бита** — 4, 10 и 13. Одно ли это и то
же в разных прошивках, на одном устройстве не проверить.

**Сахар крови у ES100 всегда пуст** — поле в протоколе есть, датчика нет.

**PAI считает браслет по своей модели.** Формулу вендор не публикует, пересчитать
эти баллы нельзя ни на клиенте, ни на сервере.

Пропуск любого бита не ломает кадр, но **молча теряет значение**: именно так у
нас пропадали PAI и набор высоты.

### 8.6. Сон `01 C6 AA 04`

Два служебных байта заголовка, затем записи по семь байт:

```
<BE32 время> <BE16 минуты> <стадия>
```

| Код | Стадия        | Код | Стадия         |
| --- | ------------- | --- | -------------- |
| 1   | глубокий      | 5   | дневной сон    |
| 2   | лёгкий        | 6   | храп           |
| 3   | пробуждение   | 7   | начало сессии¹ |
| 4   | быстрый (REM) | 8   | конец сессии¹  |

¹ Служебные маркеры нулевой длительности: ими устройство само режет ночь на
сессии. Проверено на живой выгрузке — в одном ответе лежали дневной сон на 27
минут и ночь на восемь часов, разделённые именно ими.

**Константы взяты из SDK вендора.** В популярном публичном реверсе третья и
четвёртая стадии перепутаны местами, из-за чего быстрый сон превращается в
пробуждения и ночь выглядит рваной.

`snore` устройство пишет, но микрофон под него не задействует — детектором храпа
это не является.

### 8.7. Стресс `01 E1 AA 02`

Первые два байта — общая длина, дальше посуточные блоки:

```
<BE32 полночь> <BE16 шаг в минутах> <по байту на каждую ячейку сетки>
```

Ячеек — `1440 / шаг`. **Ноль означает «замера не было», а не «стресс равен
нулю».** Живьём: тело ответа 1448 байт, шаг 1 минута, ненулевых 126 — реальный
замер примерно раз в десять минут. Шкала значения — 1–100.

### 8.8. Список тренировок `01 E8 AA 01`

Первые два байта — количество, дальше записи по восемь байт:

```
<BE16 id> <BE16 индекс> <отрезков темпа> <секций> <писался ли SpO₂> <резерв>
```

**Два индекса, а не один.** В чужих разборах их регулярно склеивают в одно число
— «тренировка №3610» вместо «третья тренировка, двадцать шестой отрезок».
`индекс` — порядковый номер на устройстве: после сброса нумерация начнётся
заново.

### 8.9. Сводка тренировки `01 E8 AA 02`

Модальный TLV. `01` — id (BE16), `02` — номер вида спорта, `03` и `04` — начало
и конец (BE32).

**Состав полей снят с устройства целиком:** на пустой запрос прошивка отдаёт
шаблон со всеми тегами и их длинами — 49 полей, 117 байт значений.

```
01:2 02:1 03:4 04:4 05:4 06:4 07:4 08:4 09:2 0A:4 0B:1 0C:1 10:2 11:2 12:4
13:1 14:1 15:4 16:1 18:4 19:2 1A:4 1B:4 1C:4 20:2 21:2 22:1 23:1 25:4 26:4
3A:4 3C:2 3D:1 3F:1 40:1 41:1 42:1 43:2 44:2 45:1 46:4 49:1 4B:2 4C:2 4D:2
4E:2 4F:2 50:2 51:2
```

**Структура известна полностью, смысл — нет.** Сопоставить тег с величиной можно
только на записанной тренировке, а их на устройстве не бывает (см. §8.10).
Выдуманная подпись хуже честного номера: по ней принимают решения как по
измеренному.

Номера видов спорта — таблица вендора `UTEDeviceSportMode` на 115 позиций
(`1` бег, `2` велосипед, `9` ходьба, `19` йога, …). Каталог конкретного браслета
читается отдельно (`01 EC AA AA`) и заметно шире: `01` сколько видов можно
держать включёнными, `03` все поддержанные номера, `04` включённые сейчас
(в каждом списке первый байт — количество). На неизвестные номера имя не
выдумывается.

### 8.10. Тренировка в историю не попадает

Проверено живьём полным циклом дважды — на минуте и на трёх минутах. После
корректного финиша с ненулевыми итогами список `01 E8 AA 01` остаётся пустым, а
сводка `01 E8 AA 02` отдаёт нули для любого номера.

**Во время занятия браслет работает датчиком, а не регистратором.** Накопить
тренировку обязан клиент из секундного потока `01 E8 AC 02` — переспросить
устройство потом будет нечего.

### 8.11. Распознанная активность: два потока

Заходы движения устройство размечает само, и живут они **не** в группе
тренировок, а отдельным каналом: счётчик на `C5`, записи на `C6`, поля `02`
(Status) и `03` (State). За сутки на живом устройстве их было 28.

Первые два байта — номер кадра, дальше записи по семь байт:

```
<тип:1> <BE32 время> <BE16 минуты>

01 | 6a a0 23 a4 | 00 03     тип 1, 3 минуты
01 | 6a a0 49 24 | 00 07     тип 1, 7 минут
01 | 6a a0 53 74 | 00 08     тип 1, 8 минут
```

**Тип во всех наблюдениях равен единице** — различать виды движения прошивка не
умеет или не сообщает, поэтому подписывать его словом нельзя.

**Чем потоки отличаются друг от друга, не установлено.** В наблюдениях записи
второго попадали внутрь окна тренировки, а первого — вне её. Признак потока
сохраняется в данных, чтобы это можно было выяснить.

Записи появляются с задержкой: за четыре минуты живого движения новых не
добавилось, самая свежая была семнадцатичасовой давности. Судя по всему, заход
дописывается после завершения, а не в момент начала.

### 8.12. Будильники `01 C7 AA AA`

Модальный TLV, и **в каждом поле первый байт значения — номер слота**:
устройство отдаёт не «будильник целиком», а «свойство такого-то будильника».

| Тег  | Значение                              |
| ---- | ------------------------------------- |
| `01` | слот (дублируется)                    |
| `02` | слот, маска дней                      |
| `03` | слот, включён                         |
| `04` | слот, час, минута                     |
| `05` | слот, имя в UTF-16BE (до 20 символов) |

Маска дней: бит 0 — воскресенье, бит 6 — суббота. `62` = будни.

### 8.13. «Не беспокоить» `01 EA AA 01`

Восемь байт подряд: весь день, по расписанию, час и минута начала, час и минута
конца, глушить вибрацию, глушить сообщения.

## 9. Диктофон: отдельный протокол

Подсистема со своими правилами. Путать с основным протоколом нельзя.

```
01 | OP | 00 | payload          ← порядок байт МЛАДШИМ ВПЕРЁД
```

Ни режима, ни номера поля, ни терминатора здесь нет: ответ приходит одним
кадром. Прогнать его через сборщик основного протокола — значит ждать
терминатора, которого в этом протоколе не бывает, до самого истечения времени.

### 9.1. Опкоды

| Код  | Действие                  | Код  | Действие                   |
| ---- | ------------------------- | ---- | -------------------------- |
| `01` | рукопожатие               | `1A` | список записей             |
| `02` | серийный номер            | `1C` | скачать диапазон           |
| `06` | память                    | `1D` | отменить скачивание        |
| `14` | начать запись             | `1E` | удалить запись             |
| `15` | пауза                     | `24` | список меток               |
| `16` | продолжить                | `26` | синхронизация меток        |
| `17` | остановить                | `28` | отмена синхронизации меток |
| `18` | подтверждение старта      | `29` | удалить метку              |
| `0D` | метка (отчёт)             | `05` | отвязать диктофон          |
| `66` | заводской сброс диктофона |      |                            |

Рукопожатие приложение вендора не делает вовсе — список и выгрузка работают и
без него.

### 9.2. Память `01 06 00`

Три числа LE32 подряд, со смещения 3: всего, свободно, байт в секунде.
Живьём — 105 519 и 105 298 единиц по килобайту, то есть около 103 МиБ.
Единица выведена эмпирически: 86 440 байт заняли 84 единицы.

Итого около **15 часов записи**. Что происходит при заполнении памяти —
перезапись по кругу или отказ записи — **не проверено**.

### 9.3. Список записей `01 1A 00`

`<..> <LE32 количество со смещения 7> <записи по 10 байт с 11-го>`

Запись: `<LE32 сессия> <LE32 байт> <LE16 тип>`.

**Сессия — это время начала записи в секундах Unix, и другого идентификатора у
записи нет.** Отсюда требование выставлять часы при каждом подключении: со
сбитыми часами весь список встаёт не в те даты, и исправить это задним числом
уже нельзя.

Длительность считается из размера: `секунды = байты / 2000`. Точно, без разбора
потока.

### 9.4. События диктофона

Приходят сами, опрашивать не нужно. Со смещения 3 — сессия LE32.

| Опкод      | Событие     | Дополнительно                                             |
| ---------- | ----------- | --------------------------------------------------------- |
| `14`, `18` | началась    | —                                                         |
| `15`       | пауза       | —                                                         |
| `16`       | продолжена  | —                                                         |
| `17`       | закончилась | байт 7 — остановлено кнопкой; байты 9–12 — размер LE32    |
| `0D`       | метка       | байты 7–10 — смещение в секундах LE32; 11–12 — номер LE16 |

**Времени события устройство не даёт.** `session` — момент начала записи, а не
момент паузы: запись на семь секунд звука может растянуться на сорок минут
стенных часов. Цикл «пауза → продолжение → пауза» по кадру неразличим — свой
идентификатор события ставит клиент.

### 9.5. Скачивание `01 1C 00`

Запрос: `<LE32 сессия> <LE32 от> <LE32 до> <LE16 тип>`. Диапазон байт — значит
**докачка после обрыва штатная**, а не хитрость.

Данные идут **отдельным потоком кадров**, а не ответом на команду:

```
<поток:1> <LE32 сессия> <LE32 позиция> <длина:1> <данные>
```

- поток `02` — звук, `05` — метки;
- позиция `FFFFFFFF` — конец файла;
- куски приходят **с позицией, а не по порядку**: собирать надо по позиции, при
  повторе кусок просто перезапишет сам себя.

Удаление (`01 1E 00`) освобождает память браслета — вызывать только после того,
как файл сохранён.

**Список меток, сохранённый на устройстве (`01 24 00`), не разобран:** раскладку
ответа проверить нечем. Живые метки приходят отчётом и разбираются точно, а этот
список нужен только после переустановки приложения — поэтому метки старых
записей теряются.

## 10. Звук: что именно лежит в файле

| Свойство  | Значение                  |
| --------- | ------------------------- |
| Кодек     | Opus                      |
| Частота   | 16 000 Гц                 |
| Каналы    | 1                         |
| Битрейт   | 16 кбит/с, жёсткий CBR    |
| Кадр      | 20 мс                     |
| Пакет     | 40 байт                   |
| Поток     | ровно 2000 байт в секунду |
| Контейнер | **нет**                   |

**Устройство отдаёт голый поток пакетов Opus.** Такой файл технически валиден, но
плеер его не откроет и часть сервисов распознавания не примет: нет заголовков,
нет частоты дискретизации, нет разбивки на страницы.

Клиент заворачивает поток в Ogg: собирает `OpusHead` и `OpusTags`, режет на
страницы по 50 пакетов, считает granule по 960 сэмплов на пакет и CRC32 по
спецификации Ogg — у него собственный вариант: полином как у Ethernet, но без
инверсий и отражения битов, готовые реализации не подходят.

**Это упаковка, а не перекодирование:** байты звука не трогаются, декодер не
нужен, размер растёт примерно на 4 % за счёт служебных страниц. Разворачивать в
PCM на телефоне бессмысленно — час записи весит 7 МБ, а после распаковки весил бы
115 МБ.

Проверено декодированием: три файла разобрались без единой ошибки, число кадров
сошлось с длительностью до сотых.

Первые байты потока — `4B 41` — **не магическое число формата**, а TOC-байт Opus
плюс счётчик кадров. Определять по ним тип файла бессмысленно.

## 11. Необратимые команды

Ни одна из них не спрашивает подтверждения на устройстве и выполняется
немедленно. Соседствуют они с безобидными по номерам полей: сброс к заводским
настройкам отличается от вибрации поиска одной цифрой.

| Действие                       | Кадр                                      |
| ------------------------------ | ----------------------------------------- |
| Заводской сброс                | `01 A5 AB 02 01 01`                       |
| Пароль (шесть цифр)            | `01 A5 AB 0C 07 01 <шесть цифр по байту>` |
| Снять пароль                   | `01 A5 AB 0C 01 00`                       |
| Снять привязку к аккаунту      | `01 E7 AB 03 01 01`                       |
| Стереть идентификатор аккаунта | `01 E7 AB 05 01 01`                       |
| Запросить сопряжение заново    | `01 E7 AB 02 01 01`                       |
| Отвязать диктофон              | `01 05 00 01`                             |
| Стереть все записи             | `01 66 00`                                |

Забытый пароль снимается только заводским сбросом — другого пути прошивка не
даёт. После сброса история на устройстве обнуляется, и дыра в данных потом
выглядит как сбой синхронизации, хотя им не является.

## 12. Что устройство не отвечает

Полный перебор всех команд чтения, какие есть в SDK вендора, по живому ES100
(09.09.2026, 111 команд). Это протокол опыта, а не выписка из документации.

**Отвечают данными — 40.** Паспорт, заряд, время, дневная сводка, история, сон,
стресс, поминутные слоты, разовый замер, будильники с пределом в десять ячеек,
«не беспокоить», лимиты уведомлений, типы сообщений, двусторонние настройки,
каталог видов спорта, состояние оператора тренировки, память диктофона, язык
прошивки, автоподсветка, все автозамеры с интервалами, непрерывные пульс и
кислород, пороги тревог по пульсу и кислороду, напоминание о малоподвижности,
поддержка погоды, единицы длины.

**Поле есть, данных нет — 8.** Единица температуры, единица давления, сахар
крови (включённость и интервал), разрешение на звонки, контакты, SOS, ответ на
SMS. Прошивка их знает, устройство не наполняет.

**Молчат вовсе — 49.** Термометр (`01 FB AA 01` и `01 FB AA 02`), классический
Bluetooth, автораспознавание занятий (`01 C9 AA 01`), журнал устройства, ChatGPT
и голосовой помощник, длина заметки, циферблаты, музыка и плейлисты, офлайн-карты
и навигация, беговые планы и курсы, цикл, утренние сводки, электронные карты и
платежи, лаборатория здоровья, звук и рисунки вибрации, мировое время, длина
дорожки и бассейна, GPS-эфемериды, состояние OTA JieLi.

## 13. Пределы и подводные камни

| Ограничение                           | Значение                                    |
| ------------------------------------- | ------------------------------------------- |
| Пауза между записями в характеристику | 80 мс                                       |
| Полезная нагрузка кадра               | 244 байта (пачка пишет по 230)              |
| Одновременных запросов                | 1                                           |
| Ожидание ответа                       | 12 с, у файла записи — 120 с                |
| Глубина истории на устройстве         | ~4 суток                                    |
| Кадров истории за запрос              | потолок 120 (счётчик приходит одним байтом) |
| Кадров распознанной активности        | потолок 60 на поток                         |
| Ячеек будильника                      | 10 (прошивка сообщает сама)                 |
| Память диктофона                      | ~103 МиБ ≈ 15 часов                         |
| Соединений с браслетом                | 1 на всё приложение и на весь телефон       |

Отдельно стоит помнить:

- **часы браслета уходят** при потере связи, и это единственное объяснение
  сдвинутых дат в истории; расхождение читается до синхронизации;
- **ответ на неподдержанное поле — пустое эхо**, неотличимое от ответа без
  данных; поэтому источник истины о возможностях — маски, а не перебор команд;
- **живой отчёт слабее истории**: он несёт незавершённую минуту, и перезаписывать
  им готовую нельзя;
- **тренировка нигде не хранится** — если клиент не накопил секундный поток, её
  не существует.
